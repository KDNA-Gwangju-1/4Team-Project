# v10 — 보행·배경·카메라를 함께 수정

## 조사한 제작 원칙

- [SLYNYRD: Human Walk Cycle](https://www.slynyrd.com/blog/2024/5/24/pixelblog-50-human-walk-cycle): 실제 보행 참고에서 접지, 체중이 내려가는 자세, 다리 교차, 앞으로 발을 내미는 자세를 구분한다. 팔다리의 반대 방향 움직임과 몸의 상하 이동이 중요하며, 출력 프레임 수만 높이는 것이 해답은 아니다.
- [Aseprite 공식 애니메이션 문서](https://www.aseprite.org/docs/animation/): 프레임·레이어·셀을 분리하고 프레임별 시간을 조절하며, 어니언 스킨과 미리보기로 자세 연결을 확인하는 작업 흐름을 설명한다.
- [Disney Animation 제작 과정](https://www.disneyanimation.com/process/animation/): 타이밍, 명확한 동작 전달, 준비 동작, 후속 움직임과 부차 움직임을 캐릭터 연기의 기본 원칙으로 설명한다.
- [Godot 공식 2D Parallax 문서](https://docs.godotengine.org/en/4.4/tutorials/2d/2d_parallax.html): 거리별 배경이 카메라에 서로 다른 비율로 반응하면 깊이감을 표현할 수 있다.

외부 영상·원화·음원을 다운로드해 사용하지 않았다. 위 자료는 동작과 화면 구성의 참고이며, 특정 사람의 보행을 모션 캡처한 결과가 아니다.

## v9에서 확인한 원인

고정 배경, 서로 다른 원화의 팔다리 윤곽을 섞는 보간, 자세마다 다시 가속·감속하는 동작 연결, 접지 위치의 부재가 함께 작용했다. v9는 부드러운 출력 타이밍을 제공하지만 실제로 서 있는 발을 고정하지 못했다. 배경만 움직여 이 문제를 숨기는 방식은 적용하지 않았다.

## 적용

### 보행

- 접근 및 문턱 보행은 정지 원화 한 장의 골반·무릎·발목 기준점으로 변형한다. 서로 다른 두 다리 실루엣을 디졸브하지 않는다.
- 각 다리는 한 주기에서 접지 60%, 발을 앞으로 옮기는 구간 40%로 설계했다. 이 비율과 다리 길이는 이 캐릭터의 연출용 설정이다.
- 완전히 보행 상태에 들어간 접지 구간에는 발목의 월드 목표 위치가 고정된다. 반대발은 높이를 올려 앞으로 이동하고, 두 관절 계산으로 무릎을 굽힌다.
- 멈출 때는 보행 변형이 정지 원화로 점진적으로 돌아간다. 문턱 보행의 시작 위상 오차와 방향 전환 직전의 불완전한 감속을 검사 과정에서 수정했다.
- 뒤에서 보는 신발은 별도 조각으로 유지한다. 바지 변형 때문에 신발이 길어지거나 비틀리는 문제를 줄인다.
- 옆걸음은 앞·뒤 다리를 별도 레이어로 계산해 다리가 교차할 때 윤곽이 접히거나 두 개로 겹치는 문제를 줄였다.
- 문 열기·방향 전환에는 기존 원화와 보정된 대응점을 유지한다. 중간 자세마다 불필요하게 멈추던 가속·감속을 제거했다.

### 배경·카메라

- 기존 복도 그림을 바닥, 천장, 왼쪽 벽, 오른쪽 벽, 먼 출입문 평면의 깊이에 맞춰 재투영한다.
- 카메라는 문 앞까지 0.38m, 문턱 구간에서 0.08m를 추가로 전진한다. 퇴장 때 오른쪽으로 0.05m 이동하고 시선을 약 1.15도 돌린다.
- 카메라 시작·끝의 속도와 가속도가 갑자기 바뀌지 않도록 곡선을 사용했다. 인위적인 반복 흔들림은 넣지 않았다.
- 캐릭터, 문, 문틀 가림에도 같은 카메라를 사용한다. 배경만 따로 확대하는 방식이 아니다.

### 픽셀 출력

원본은 세밀한 일러스트와 픽셀풍 배경을 조합한 것이다. 이번에 모든 픽셀을 수작업으로 다시 찍은 것은 아니다. 기본 출력은 화면 전체를 공통 960×540 격자로 모은 뒤 최근접 방식으로 정확히 2배 확대한다. 1920×1080, 60fps, 13.4초, 무음이다. `--smooth-export`는 격자 확대 없이 출력하는 비교 옵션이다.

## 재현 및 검수

```sh
python ArtSource/Chapter2Ending/DetectiveExit/render_v10.py
python ArtSource/Chapter2Ending/DetectiveExit/validate_v10.py
```

Python·OpenCV·NumPy·FFmpeg 설치는 README의 기존 로컬 도구 안내를 따른다. `--preview`는 주요 16시점만 렌더한다. `output/ending-v10`은 중간 산출물 폴더이며 저장소에 올리지 않는다.

Validation-v10-file.json은 전체 프레임 디코딩, 출력 규격, 해석적 관절 길이, 완전 접지 구간의 목표 발목 이동량과 가까운/먼 기준점의 카메라 이동 차이를 기록한다. 이는 그림 속 발 픽셀을 추적한 수치나 자연스러움 점수가 아니다. 주요 장면과 확대 연속 프레임도 별도로 확인했다.

최종 결과: 804프레임 전부 디코딩, 530개의 연속 접지 검사 구간에서 목표 위치 이동 0, 관절 길이 오차는 부동소수점 정밀도 범위. 배경 샘플링 범위를 벗어난 픽셀 0. 카메라 전진 구간의 가까운 기준점 이동은 약 166px, 먼 기준점은 약 10px였다. 두 지점의 좌표가 다르므로 이 수치를 보편적인 시차 비율로 해석하지 않는다.

`Comparison-v9-v10.mp4`는 왼쪽 고정 카메라 v9, 오른쪽 수정본 v10이다. v10의 동작 시간이 조금 길어져 같은 시각의 자세가 정확히 일치하지는 않는다. 비교용으로 v9의 마지막 화면을 1초 연장했다. 이 검수는 수치·표본 프레임 확인이며 사람이 실시간으로 전체 영상을 감상한 평가는 아니다.

## 한계와 범위

2D 원화에 관절 목표를 적용한 컷아웃 애니메이션이다. 근육·옷감 물리나 완전한 3D 인체 리깅은 아니다. 문 열기·방향 전환에는 원화 간 국소 잔상이나 형태 변화가 남을 수 있다. 복도 깊이는 한 장의 그림으로 근사했으므로 화분처럼 평면에서 튀어나온 물체의 시차는 정확한 3D와 다르다. 카메라 이동량을 제한해 이 왜곡을 줄였다. 실제 게임 씬과 오프닝 연결, 사운드는 변경하지 않았다.
