# 전체 씬 디자인 검토 — 2026-09-25

## 검토 범위와 한계

- Build Settings에 활성화된 게임 씬 8개 전부를 별도 Preview Scene으로 열어 계층, 컴포넌트, 텍스트, 시작 카메라 구도를 확인했다. 원본 씬은 저장하거나 수정하지 않았다.
- MainMenu, Game, BrightDream, BadDream 1·2·3의 정적 카메라 렌더를 확인했다. HospitalRoom은 UI를 제외한 병실·복도 추가 시점도 확인했다. Loading은 원본 배경 이미지와 설정·전환 코드를 확인했다.
- BadDream_stage2는 실행 중인 실제 화면도 캡처했다. 다른 씬 전체를 플레이하거나 보스전·엔딩을 끝까지 재현한 검토는 아니다.
- 정적 Preview에는 Awake/Start 기반 UI 스킨·숨김·카메라 연출이 적용되지 않는다. Preview에 보이는 구형 HUD나 로딩/조작 안내 겹침을 실제 게임 결함으로 판정하지 않았다. Loading-preview.png의 빈 화면도 실행 결함으로 판정하지 않았다.
- 검토 중 Editor가 재생 상태에서 편집 상태로 바뀌었다. 다른 작업과 충돌하지 않도록 현재 씬 전환/플레이 조작은 하지 않았다.
- Git 변경 사항을 읽어 기존 작업을 대조했지만, 개별 변경의 작성자가 Claude인지까지 식별하지는 않았다.
- Asset Store 예제 하늘 씬, __TEMP_REFERENCE, ManualBackups는 신규 디자인 대상에서 제외했다. 8개 게임 씬의 Missing Script는 0개였다.

## 권장 작업 순서

### 1. 엔딩 이후 완료 화면과 복귀 동선 — 높은 우선순위, 코드 확인

- 근거: Assets/Scripts/2d_scripts/Stage3EndingCutscene.cs:208의 PlayEnding은 대화·걸어가기·흰색 페이드 후 whiteHold 대기에서 종료된다(281~282행). 해당 파일에 후속 씬 이동이나 완료 UI가 없다.
- 작업: 엔딩 일러스트/짧은 마무리 문구, 크레딧, 메인 메뉴 복귀 버튼을 설계한다. 기존 동생으로 돌아오는 연출은 유지한다.
- 검증: 실제 보스 클리어부터 마지막 화면·복귀까지 진행. 흰 화면 유지가 의도된 미완료 경계인지 제작 의도 확인.

### 2. 챕터2 배경과 게임 요소의 구분 — 높은 우선순위, 화면 기반 디자인 판단

- 근거: BadDream_stage2-current.png 및 BadDream 1·2·3 Preview. 큰 액자/그림과 발판이 강한 외곽선·보라 계열을 공유하며, 화면 상부는 반복 그림으로 밀도가 높다.
- 작업: 플레이 경로 뒤의 배경 대비와 장식 밀도를 낮추고, 착지면 상단을 일관되게 강조한다. 적/탄환은 장식과 구별되는 색·명도 기준을 둔다. 구간별로 대표 그림을 남겨 반복감을 줄인다.
- 검증: 실제 이동·대시·점프·피격 상황, 16:9 및 현재 넓은 Game View에서 확인. 어려운 길 찾기 자체가 의도인 구간은 보존한다.

### 3. 챕터1 보스 전용 약점 연출 — 높은 우선순위, 설정·코드 확인

- 근거: Assets/Scenes/SD_BrightDream_Blockout_Rect.unity:200100 weakpointVisual={fileID:0}. BossWeakpointController에 본체 색상 변경이 임시 표시라는 설명 및 구현이 있다.
- 작업: 약점의 위치·활성 상태를 보여주는 봉제 균열/코어, 노출 시 맥동, 명중 시 파편과 짧은 반응, 닫힐 때 소멸을 제작한다. 기존 3회 정화→3.5초 노출→6회 명중 규칙은 유지한다.
- 검증: 보스 뒤 균열과 약점의 밝기가 경쟁하지 않는지 실제 전투에서 확인. 새 약점이 실제 판정 위치를 오해시키지 않아야 한다.

### 4. 일시정지 확인창 버튼 배치 — 중간 우선순위, 코드상 계산 확인

- 근거: Assets/Scripts/UI/PauseMenu.cs의 ConfirmPanel 높이는 360. 버튼 row2/row3은 위에서 262/338 아래에 배치되고 높이는 62여서 마지막 버튼 하단이 400까지 내려간다. 패널 하단보다 40 길다.
- 작업: 확인창용 별도 버튼 행 또는 가로 예/아니요 배치로 바꾸고 패널 여백을 맞춘다. 일시정지 메뉴 자체는 이미 구현되어 있으므로 신규 제작으로 중복 배정하지 않는다.
- 검증: 메뉴 복귀/게임 종료 확인 화면의 실제 캡처, 키보드 선택 및 작은 해상도 검증. 현재 작업 중인 변경일 수 있으므로 수정 직전 최신 파일 재확인.

### 5. 챕터2 보스 체력바 마감 — 중간 우선순위, 설정·코드/정적 화면 확인

- 근거: BossHealthBarUI2D.cs는 이름·수치·잔상 게이지를 갱신한다. 일반 HUD의 ChapterHudStyle 적용과는 별개이고, 현재 정적 화면은 긴 붉은 막대 중심이다.
- 작업: 악몽 테마 프레임, 이름과 체력의 읽기 순서, 페이즈 표시를 정리한다. 기존 잔상 게이지와 페이즈 연출은 유지한다.
- 검증: 실제 페이즈1/2, 피격·전환·사망·재시작에서 HUD 상태 확인. Preview에 빈 이름이 보이는 것은 Start 미실행 때문이므로 이름 누락 버그로 처리하지 않는다.

### 6. 로딩 화면의 시간·안내 구성 — 중간 우선순위, 설정 확인

- 근거: Assets/Scenes/Loading.unity:152 minimumDisplayTime=9. LoadingScreen에는 이미 팁과 그림 비율 보정이 존재한다.
- 작업: 최소 대기 시간을 실제 로딩과 연출 목적에 맞춰 조정하고, 병원/꿈 진입/메뉴 복귀 안내를 구분한다. 고정 9초가 제작 의도라면 유지하되 기다리는 이유를 보여준다.
- 검증: 빠른 PC에서도 각 이동 시 얼마나 기다리는지, 팁을 읽을 시간이 충분한지 확인.

### 7. 병원과 정원의 국소 디테일 — 낮은 우선순위, 선택적 미술 작업

- 병원: 복도 문·등 반복 사이에 구역 표식/게시판을 제한적으로 추가하고 환자별 개인 소품으로 구분한다. 침대 번호·의료 패널·복도 연장은 이미 존재한다.
- 정원: 온실·다리·전투 구역은 이미 구축되어 있다. 소품 추가보다 주요 단서 주변 여백, 표지판 내용, 보스 뒤 균열 강도 조정을 먼저 검토한다.
- 정적 Preview 조명과 실제 런타임 조명이 다를 수 있어 최종 밝기 조정은 실행 화면 기준으로 한다.

## 기존 제안에서 제외한 중복 작업

- 대화창 전체 통일: SubtitleUI, DialogueUI, ClueManager, DialogueWindow2D에 ChapterDialogueSkin 적용 존재.
- 단서 강조 신규 개발: ClueOutlineController의 기본/호버 외곽선과 맥동 구현 존재.
- 체력·대시·손전등 HUD 전체 신규 제작: ChapterHudStyle 기반 공용 스타일 존재; 실행 중 Stage2에서 확인.
- 씬 전환 기능 신규 제작: SceneFader, ScreenWarpTransition, LoadingScreen 및 전환 호출 존재.
- 사망/다시하기 화면 신규 제작: GameOverController, DeathRetryUI2D가 존재하고 스킨 호출도 있음.
- 병원 침대 번호·의료 패널 추가: 현재 씬에 이미 존재.
- 챕터2 페이즈2 이미지 재제작·재시작 크기 수정: 앞서 작업된 변경이 있으므로 새 디자인 과제로 재등록하지 않음. 이후 변경이 있으면 회귀 검증 대상.
