# 몹 에셋 5종 + 보스 1종 (펠트 크래프트 스타일)

레벨·벽면 에셋과 같은 v3 펠트-CG 톤으로 맞춘 적 캐릭터 5종.
VARCO 3D 로 이미지 → 메시 → 리깅 → 모션까지 뽑고, Blender 에서 한 파일로 합쳤다.

## 파일 구성

몹 1종당 GLB 파일 **1개**다. 그 안에 메시 + 스켈레톤 + 모션 2개가 모두 들어 있다.

| 파일 | 몹 | 공격 모션 | 사망 모션 | 용량 |
|---|---|---|---|---|
| `01_cotton_soldier.glb` | 검은 솜뭉치 병사 | 3.71s | 8.83s | 5.9MB |
| `02_patchwork_scarecrow.glb` | 천조각 허수아비 | 1.46s | 5.04s | 7.4MB |
| `03_button_knight.glb` | 단추눈 인형 기사 | 5.04s | 3.21s | 7.0MB |
| `04_yarn_spiderling.glb` | 털실 거미 인간 | 4.54s | 1.75s | 8.8MB |
| `05_felt_golem.glb` | 펠트 골렘 | 6.33s | 7.88s | 6.4MB |

`*_concept.png` 는 3D 변환에 쓴 원본 콘셉트 이미지다. 나중에 같은 몹을 다시 뽑거나
다른 색 변형을 만들 때 참고용으로 넣어 뒀다.

애니메이션 클립 이름은 다섯 종 모두 **`Attack` / `Death`** 로 통일했다.
AnimatorController 를 하나 만들어 5종에 돌려 쓸 수 있다.

## 스펙

- 메시 20,000 트라이앵글, 머티리얼 1개
- 텍스처 3장 (베이스컬러 / 노멀 / ORM), 각 1024×1024
- 스켈레톤 **본 23개**, 이름은 Mixamo 표준
  `Hips / Spine / Spine1 / Spine2 / Neck / Head /
   Left·RightShoulder / Arm / ForeArm / Hand /
   Left·RightUpLeg / Leg / Foot / ToeBase`
- 모션은 전부 **제자리 재생(in-place)** 이다. 이동은 게임 코드가 처리한다는 전제.
- 모델 높이 약 0.7 ~ 1.0 유닛. 배치할 때 게임 스케일에 맞춰 키우면 된다.

## Unity 로 가져올 때

1. GLB 를 `Assets/` 밑에 넣으면 Unity 가 알아서 읽는다.
2. Inspector → **Rig** 탭에서 Animation Type 을 **Humanoid** 로 바꾸고 Apply.
   본 이름이 Mixamo 표준이라 아바타 매핑이 자동으로 잡힌다.
3. **Animation** 탭에 `Attack` / `Death` 클립이 보인다. 공격은 Loop Time 끄고,
   사망도 끈다 (마지막 프레임에서 멈춰야 소멸 연출로 이어진다).
4. 텍스처는 ORM 한 장에 세 채널이 묶여 있다 (R=오클루전, G=러프니스, B=메탈릭).
   URP Lit 에 그대로 못 꽂으니 Metallic/Smoothness 로 변환하거나,
   펠트 재질이라 메탈릭이 0에 가까우므로 그냥 베이스컬러 + 노멀만 써도 충분하다.

# 보스 : 유니콘 (06_unicorn_boss)

몹 5종의 **정확히 3배 크기**로 만든 4족 유니콘 보스.

| | |
|---|---|
| 파일 | `06_unicorn_boss.glb` (8.4MB) |
| 키 | **2.700 m** (몹 0.900 m 의 3배) |
| 폴리곤 | 80,000 트라이앵글 |
| 텍스처 | 4096 베이스컬러 + 4096 노멀 + 2048 ORM |
| 원점 | 발밑 한가운데. 바닥에 그냥 놓으면 선다 |
| 셰이딩 | 35도 기준 스무스 |

## 3배로 키워도 안 깨지게 하려고 한 것

크게 만들면 무너지는 건 두 가지다. 텍스처가 뭉개지거나, 실루엣이 각져 보이거나.
거기에 하나 더, 이 세계관에서는 **직물의 결 크기**가 어긋나면 혼자만 다른 재질처럼 보인다.

| 항목 | 일반 몹 | 보스 (3배) | |
|---|---|---|---|
| 베이스컬러 텍셀 밀도 | 1,138 px/m | **1,517 px/m** | 몹보다 33% 선명 |
| 면 한 변 길이 | 10.8 mm | 18.5 mm | 1.7배지만 육안으로 각짐 없음 |
| 표면 밀도 | 20,553 tri/m2 | 6,968 tri/m2 | |

텍셀 밀도는 이렇게 잡았다. 몹은 0.9m 에 1024 텍스처라 m 당 1138px 이다.
2.7m 에서 같은 밀도를 내려면 3073px 이 필요하므로 4096 을 썼다.

### 제일 중요한 것 — 뜨개 눈 크기

작은 몹과 **같은 비율**로 뜨개 무늬를 넣고 3배로 키우면 실이 3배 굵어진다.
그러면 혼자만 밧줄로 짠 것처럼 보인다. 이게 이질감의 진짜 원인이다.

그래서 이미지 생성 단계에서 미리 가늘게 뽑았다. 프롬프트에 이 문단을 넣었다.

> this creature is three times larger than the other characters in the set, so the
> knitting must be worked in a FINE yarn, not a chunky one ... about a third of the
> relative stitch size you would use on a small hand-sized plush toy.

같은 실제 크기로 확대해 비교하면 몹의 직물 결과 보스의 뜨개 눈이 거의 같은 굵기로 나온다.

`check_scale.py` 로 언제든 다시 잴 수 있다.

## 아직 안 된 것 : 리깅

**이 보스에는 스켈레톤과 모션이 없다.** 지금은 정지 메시다.

VARCO 오토리거가 이 4족 유니콘을 리깅하지 못한다.

| 시도 | 결과 |
|---|---|
| quadruped / 80,000 폴리 | 실패 |
| quadruped / 80,000 폴리 (재시도) | 실패 |
| quadruped / 30,000 폴리 (리메시) | 실패 |
| quadruped / 30,000 폴리 (재시도) | 실패 |
| humanoid / 30,000 폴리 | 태스크는 성공. 하지만 **본 23개 중 16개가 한 점에 뭉침** |

메시 자체는 정상이다. 폴리곤 수도 원인이 아니다 (30,000 으로 낮춰도 실패했고,
같은 메시에 humanoid 를 걸면 태스크는 통과한다).

의심되는 원인은 `Generate3D` 의 **`tPose` 를 0 으로 준 것**이다.
몹 5종은 전부 1 이었고 전부 리깅됐는데 유니콘만 0 이었다.
말에 T 포즈는 의미가 없다고 판단해서였는데, 리거가 그 정규화 단계를 전제한다면
본이 한 점에 뭉치는 증상과 맞아떨어진다. `tPose: 1` 로 검증하려 했으나
VARCO 메시 생성이 93.5% 에서 한 시간 넘게 멈춰 결론을 내지 못했다.

### 리깅이 필요해지면

1. `tPose: 1` 로 다시 뽑아 quadruped 리깅을 재시도한다 (가장 유력)
2. 발굽을 진하고 뚜렷한 말 발굽으로 바꿔 다시 뽑는다
   카탈로그가 "발 형태를 감지해 발바닥/발굽 스켈레톤을 고른다" 고 하므로
   뜨개로 된 뭉툭한 발굽이 분류에 실패했을 수 있다
3. 2족 직립 유니콘으로 바꾼다. 몹 5종에서 검증된 경로라 확실하지만 4족을 포기하게 된다

4족 리그로 쓸 수 있는 모션은 이렇다.

- 공격 : `horse_rear_up` (앞발 들고 내려찍기) — **이거 하나뿐이다**
- 사망 : `horse_death_front`
- 그 외 : `horse_idle_1` / `horse_stand` / `horse_walk` / `horse_trot` /
  `horse_canter_*` / `horse_gallop_*` / `horse_backward_walk`

## 소멸(디졸브) 연출

에 대해

VARCO 애니메이션 카탈로그에는 **디졸브처럼 사라지는 모션이 없다.**
그래서 표준 방식대로 나눴다.

- **쓰러지는 동작** → 여기 들어 있는 `Death` 클립
- **사라지는 효과** → Unity 디졸브 셰이더 (노이즈 텍스처의 clip 임계값을 올려 깎아 내는 방식)

둘이 독립이라 `Death` 재생이 끝나갈 때쯤 셰이더 값을 0→1 로 올리면 된다.
몹마다 사라지는 색이나 속도를 다르게 주고 싶어도 모델은 건드릴 필요가 없다.
