## 스타일 일치 확인
5종 모두 기존 Dream1 에셋과 동일한 v3 펠트-CG 톤으로 나왔다.
- 펠트 섬유 질감, 대시 스티치 라인, 단추 디테일 확인
- 플라스틱 광택 없음 (프롬프트에서 명시적으로 배제한 것이 먹혔다)
- 평평한 흰 배경, 단일 오브젝트

## 3D 진행 전 확인할 것

**02 와 05 는 각도를 다시 뽑는 편이 낫다.**
둘 다 거의 정측면으로 나와서 옆면 프로파일만 보이고 깊이가 안 보인다.
기록된 사례(01_wall_sky_panel / 02_wall_corner)처럼 Generate3D 가
납작하게 만들 위험이 있다. EditImage 로 각도만 돌리거나
프롬프트에 `rotated 35 degrees toward the camera` 를 추가해 재생성.

**05 의 털실 나선은 폴리곤이 아니라 텍스처로 가야 한다.**
20,000 폴리에서 실 한 가닥씩 살릴 수 없다. 노멀맵으로 표현되도록
usePbrTexture 1 + textureSize 2048 권장.

**03 의 벌린 입은 오목면이라 메시가 막힐 수 있다.**
생성 후 입 안쪽이 메워졌는지 확인 필요.

## 3D 단계 설정 (프롭용)
```
polygonCount 20000 / topology tri / tPose 0 / usePbrTexture 1 / textureSize 1024
```
몹과 달리 **tPose 0**. 리깅하지 않는 프롭이다.

## 스케일
몹 0.900 m 기준, 손에 드는 장난감 총은 **0.20 ~ 0.25 m**.
생성 후 `varco-mobs/check_scale.py` 로 검증할 것.

## 크레딧
이미지 20 × 5 = 100 소모.
Generate3D 는 채택본만 (200/개).

# 3D 생성 결과 (2026-09-21)

5종 전부 생성 완료. 1,000 크레딧 소모. `01_glb/` 에 GLB, `02_preview/` 에 4방향 렌더.

## 검증 결과 — 5종 전부 통과

| # | 크기 (m) | 두께비 | 폴리곤 | 텍스처 | 판정 |

| 02 펠트 물총 | 0.441 × 0.836 × 1.000 | 0.442 | 20,000 | 3장 | 통과 |
| 03 공룡 아가리 총 | 0.618 × 1.002 × 0.802 | 0.617 | 20,000 | 3장 | 통과 |
| 04 별날개 요술총 | 0.499 × 0.955 × 1.001 | 0.499 | 20,000 | 3장 | 통과 |

**납작해진 것은 없다.** 02 와 05 가 정측면 이미지라 판때기가 될까 우려했으나
두께비 0.442 / 0.336 으로 기준(0.18)을 크게 넘겼다. 우려는 빗나갔다.
05 가 상대적으로 얇은 것은 달팽이 껍데기가 원래 납작한 원반이라 정상이다.

## 개별 확인

- **01** 최상. 지느러미가 사방에 제대로 달렸고 나선 총구도 살았다.
- **02** 측면 실루엣 양호. 누빔 물탱크 패널 유지. 정면은 다소 좁다.
- **03** **입 안쪽이 메워지지 않았다.** 이빨과 혀가 뚫린 채로 나왔다. 우려했던 문제 없음.
- **04** 별·구름 아플리케와 털실 스월 손잡이 모두 유지.
- **05** 털실 나선이 형상으로 살아남았다. 2048 텍스처가 유효했다.

## 공통 한계 — 뒷면이 밋밋하다

5종 모두 **뒷면 디테일이 앞면보다 현저히 단순하다.** 단일 이미지 기반 생성의
구조적 한계로, 소스 이미지에 없는 면은 매끈한 덩어리로 채워진다.
1인칭/3인칭에서 총을 앞쪽으로 들면 문제되지 않지만, 뒷면이 보이는 연출이
있다면 리터치하거나 멀티뷰로 재생성해야 한다.

## 텍스처 확인
베이스컬러 평균 RGB (63, 85, 120) — 채도 정상. 노멀맵·ORM 포함 3장.
`02_preview/` 렌더가 뿌옇게 보이는 것은 렌더 스크립트의 조명이 과노출된
탓이며 에셋 자체의 문제가 아니다.

## 임포트 시 스케일

VARCO 가 최장축을 1.0 m 로 정규화해서 내보낸다. 5종 모두 마찬가지다.
손에 드는 장난감 총 목표 0.20~0.25 m 에 맞추려면 **0.25 배**로 줄일 것.
몹 0.900 m 과 나란히 놓고 한 번 확인하는 편이 좋다.

| 10 통통 버블 저그 | 0.517 × 1.001 × 0.942 | 0.516 | 20,000 | 2 (본체+돔) |

## 떠 있는 방울 문제 — 해결됨

v2 재생성(방울을 전부 몸통에 부착)이 의도대로 먹혔다.
**파편은 하나도 남지 않았다.** 2조각인 3종도 파편이 아니라 덩치 큰
의도된 부속(링 완드 / 후프 / 돔)이며, 위치가 겹쳐 있어 Unity 에서
단일 GameObject 로 다루면 된다.

08 고래는 폼폼 다발이 머리에 완전히 융합되어 1개로 나왔다.

## 측정 함정 — loose parts 를 그냥 세면 안 된다

**VARCO 출력은 정점이 용접되어 있지 않다.** 임포트 직후 loose parts 를 세면
표면 패치가 167~605개로 잡혀 아무 의미가 없다. 반드시 `remove_doubles`
(threshold 1e-4) 로 병합한 뒤 세야 실제 덩어리 수가 나온다.

| | 병합 전 | 병합 후 |
|---|---|---|
| 06 | 605 | 2 |
| 10 | 167 | 2 |
| 01 | (미측정) | 1 |

`00_docs/count_loose_parts.py` 에 병합 단계가 들어 있다.

## 개별 확인

- **06** 링 완드의 **구멍이 메워졌다.** 열린 고리가 아니라 납작한 원반이 됐다. 실제 결함.
- **07** 최상. 고리 6개가 전부 뚫린 채로 살아남았다. 비눗방울 총으로 가장 잘 읽힌다.
- **08** 양호. 고래 몸통이 꽉 찼고 폼폼 다발도 붙었다. 다만 총보다 인형에 가깝다.
- **09** 후프가 열린 고리로 살아남았다. 털실 감은 질감이 요철로 표현됐다. 본체는 다소 가늘다.
- **10** 링 완드는 뚫렸으나 **튤 돔이 불투명한 흰 공**이 됐다. 안의 폼폼이 안 보인다.

## 남은 작업 후보

1. **06 링 구멍 뚫기** — Blender 에서 부울 또는 재생성
2. **10 돔 반투명 처리** — Unity 에서 해당 머티리얼만 알파 적용하면 안쪽 폼폼이 살아난다
3. 전 모델 공통 — 뒷면이 앞면보다 단순하다 (1차와 동일한 구조적 한계)
